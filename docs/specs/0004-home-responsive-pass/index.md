# 0004. Home responsive pass on shadcn primitives

**Date**: 2026-09-29
**Status**: Done

## Summary

This decision makes the Figma exact Home page work on every screen from 360px phones to wide desktops, without losing the desktop match. From 1280px (`xl`) up the page keeps the exact Figma layout; below that, sections stack and the overlapping image clusters scale down as one piece. Every interactive primitive moves onto shadcn (a copy in component kit built on Radix, an accessible behavior library), styled with ByteSpace tokens, and the mobile header gets a hamburger on the right that opens a side panel from the right. The code is reorganized into small single purpose pieces so the later app shell feature can lift the header and footer out cleanly.

## Requirements

**User stories**:

- As a visitor on a phone or tablet, I want Home to read cleanly with nothing cut off or scrolling sideways, so I can browse courses on any device.
- As a visitor on a phone, I want a menu button on the right that opens the navigation in a side panel, so I can reach every page with one thumb.
- As a frontend engineer, I want Home built from shadcn primitives and small focused components, so changes stay local and the header and footer can move into a shared shell later.

**Acceptance criteria** (the contract, each criterion is IDed and independently checkable):

- **AC-1**: At widths 360, 390, 640, 768, 1024, 1280, 1440 and 1536 the page never scrolls sideways (`document.documentElement.scrollWidth` equals the viewport width). Content is fluid with side padding of 16px below `md`, 24px from `md`, 32px from `lg`; from `xl` the content box is 1200px wide and centered.
- **AC-2**: From `xl` (1280) up, every section uses the desktop composition from Figma `1:1067`. At 1440 every section top sits within 4px of the value recorded before this work starts, and a side by side check against `design/figma-assets/exports/home.png` shows no visual regression. At 1280 decorative shapes may be cut at the screen edge, but no text, card, person image or control is clipped. Fixed composition positions apply only from `xl`.
- **AC-3**: From `lg` (1024) the header shows the full inline nav as today. Below `lg` the bar shows the logo on the left and the bag button plus a hamburger button on the right. The hamburger opens a panel that slides in from the right, about 80% of the screen wide and at most 320px, over a dimmed backdrop, listing every link in `data/navLinks.ts` (Home, Courses, Creators today; the current page marked with `aria-current="page"`), then Sign In and a Join Us button.
- **AC-4**: The menu panel closes on a link tap, Escape, a backdrop click and its close button; while open it traps focus and locks page scroll; on close focus returns to the hamburger; it has an accessible name; its slide animation is off when the visitor prefers reduced motion.
- **AC-5**: Below `xl` the hero stacks: headline, body, search form (field and button side by side from `sm`, stacked below it), then one visual box holding the person, the lime circle and both floating cards (Happy Students, Learning Progress), scaled together so their relative positions match desktop and no card content is clipped.
- **AC-6**: Below `xl` Growth shows its text and stats first and its visual cluster after; Creator shows its visual cluster first and its text and checklist after. Each cluster (image plus cards plus spring) scales as one piece like the hero visual. Stats wrap instead of overflowing.
- **AC-7**: Decorative 3D shapes in the hero and CTA are hidden below `lg`; from `lg` to `xl` only the named edge subset shows (hero `spring-lime`, `cylinder-lime`; CTA `spring-lime-top`, `cylinder-white`) and none of them overlaps text or a control; the full Figma set shows from `xl`.
- **AC-8**: Below `lg` the 18 course category tabs sit in one horizontally scrollable row with a fade at the scrolling edge; from `lg` they wrap into centered rows like Figma. Arrow keys, Home and End move between tabs; the "+ More" link sits outside the tab list. The course grid shows 1 column below `sm`, 2 from `sm`, 3 from `lg`; cards are fluid and fill their column at every width, and from `xl` the grid uses three 373px columns so the 1440 view is unchanged.
- **AC-9**: Partner logos form a centered grid of 2 columns at base and 3 from `sm`, then one row from `lg`. Category cards stay 2, 3 and 6 columns (base, `sm`, `lg`). Testimonials show 1 column below `lg` and 3 in a row from `lg`. The CTA band is centered with content driven height below `lg` and a full width Join as Creator button below `sm`, keeping its grid pattern. The footer stacks logo and newsletter first (email field and button stacked below `sm`), then link columns in 2 columns (3 from `sm`), then copyright above the legal links, which wrap below `md`.
- **AC-10**: Headings scale fluidly between 360 and 1280 and reach their exact Figma size (72px hero, 44px section, 24px small) from `xl`; heading line heights are relative so lines never overlap at any width. Paragraph text (`body-l`, `body-m`) is at least 14px below `md` and at least 16px from `md`; captions, card metadata and legal text keep their `body-s`/`body-xs` tokens.
- **AC-11**: Every interactive control (links in the menu, tabs, buttons, inputs, hamburger, bag) has a touch target of at least 44px at widths below `lg`.
- **AC-12**: shadcn is initialized on Radix with lucide icons (`components.json` present); `components/ui/` contains `sheet`, `button`, `input`, `tabs`, `card` and `avatar`; Home uses them for every interactive primitive, card surface and avatar. shadcn's semantic theme variables resolve to ByteSpace tokens in `app/globals.css`, light only (no dark variant). ByteSpace looks exist as named variants inside those components.
- **AC-13**: Components are organized as `components/ui/` (shadcn only), `components/site/` (`SiteHeader`, `MobileNav`, `SiteFooter`), `components/home/sections/` (one file per section) and `components/home/cards/`. Shared `Section` and `SectionHeader` replace repeated padding, width and header class strings; `Container` is the one width primitive. Only `MobileNav`, `CourseTabs`, the hero search form and the newsletter form are client components. Desktop positions live as typed constants beside the component that renders them.
- **AC-14**: At 200% browser zoom on a 1280 wide window every call to action and form control stays visible and usable.

## Decision

**Chosen option**: Option 1: Fix in place, section by section, on shadcn primitives with a CSS only scaled canvas for compositions

Refactor the existing Home in place, one section at a time, keeping the 1440 match green after each step: add shadcn, map its theme to ByteSpace, add width and type foundations, then rebuild the header with a right side Sheet and make each section responsive, reusing one `ScaledCanvas` component for every overlapping composition.

**Implementation skills**: `vercel-react-best-practices` (`vercel-labs/agent-skills`, `.agents/skills/vercel-react-best-practices/`) · `vercel-composition-patterns` (`vercel-labs/agent-skills`, `.agents/skills/vercel-composition-patterns/`) · `web-design-guidelines` (`vercel-labs/agent-skills`, `.agents/skills/web-design-guidelines/`)

## Feature design

**Data model sketch**:
No change. Home stays on the static `data/` modules from spec 0003; no persistence, no migration.

**State transitions**:
Mobile menu: closed → open (hamburger click) → closed (link tap, Escape, backdrop click, close button). Course tabs: active tab id, default `featured`.

**API surface**:

| Endpoint | Method | Key inputs | Key outputs                                  | Auth   | Key errors                |
| -------- | ------ | ---------- | -------------------------------------------- | ------ | ------------------------- |
| `/`      | GET    | none       | Responsive Home HTML from `data/` and assets | public | none beyond Next defaults |

**Value sourcing**:

| Action                              | Value produced / displayed      | Source                                                                                              |
| ----------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------- |
| Render nav (bar and panel)          | link labels and hrefs (3 today) | `data/navLinks.ts`                                                                                  |
| Section vertical padding            | padding per breakpoint          | `Section` defaults (60, 80) plus the per section Figma value prop from `xl`                         |
| Canvas child positions              | local coordinates               | typed constants beside each canvas (Hero, Growth, Creator rows in the constraints table)            |
| 1440 baseline                       | section top offsets             | recorded in build step 1, before any change                                                         |
| Mark current link                   | `aria-current="page"`           | `currentId` prop from `app/page.tsx` (`home`) matched to `NavLink.id`                               |
| Open or close menu                  | open state                      | Radix `Sheet` state inside `MobileNav` (client, local)                                              |
| Menu accessible name, trigger label | "Menu", "Open menu"             | constants in `MobileNav` (invented strings)                                                         |
| Choose tab                          | active tab id                   | `CourseTabs` state, default `featured` (spec 0003)                                                  |
| Filter courses                      | visible course cards            | `data/courses.ts` filtered by active `categoryTabId`                                                |
| Scale compositions                  | scale `s` and wrapper size      | derived: canvas design `width`/`height` constants and per band `available` width (Compositions row) |
| Show or hide ornaments              | visibility per width            | `Ornament.from` field on each constant                                                              |
| Content width and padding           | padding, max width              | `Container` classes from page padding tokens and `layout.content.max`                               |
| Heading sizes                       | font size, line height          | retuned `--text-heading-*` tokens (Type row)                                                        |
| All copy, images, stats             | text and assets                 | unchanged `data/*.ts` and `public/assets/home/`                                                     |

**Key invariants**:

- The 1440 view never regresses against the Figma export; every section refactor is checked at 1440 before moving on.
- No horizontal scroll at any tested width; `overflow-x-hidden` is not used to hide a real overflow.
- Only the four named client components ship JavaScript for Home interactivity.
- No new copy or imagery beyond the two invented accessibility strings.

**Security model**:
Public marketing page. No auth, no secrets, no user data; forms stay no op stubs.

**Configuration required**:
None. New dependencies come from shadcn init and add: `radix-ui` (or the per component `@radix-ui/*` packages the CLI selects), `lucide-react`, `class-variance-authority`, `clsx`, `tailwind-merge`, `tw-animate-css`; `cn` is removed.

**Critical test scenarios** (each maps to an acceptance criterion in ## Requirements):

- Width matrix: load `/` at 360, 390, 640, 768, 1024, 1280, 1440, 1536; `scrollWidth` equals viewport width each time, verifies **AC-1**
- Desktop match: at 1440 every section top within 4px of the recorded baseline, plus a side by side screenshot check against `home.png`; at 1280 no text, card, person or control clipped, verifies **AC-2**
- Mobile menu: at 390 open the menu, check it slides from the right, Tab stays inside, Escape closes and focus lands on the hamburger, a link tap closes and navigates, page does not scroll behind it; repeat with reduced motion on, verifies **AC-3**, **AC-4**
- Stacked compositions: at 360 and 768 the hero visual, Growth and Creator clusters show every card fully, in desktop relative positions, verifies **AC-5**, **AC-6**
- Ornaments: none at 768, subset not touching text at 1024, full set at 1440, verifies **AC-7**
- Tabs and grids: at 390 tabs scroll in one row and arrow keys move focus; grid shows 1, 2, 3 columns at 390, 640, 1024, verifies **AC-8**, **AC-9**
- Type and touch: at 360 headings fit without overlap and body text is at least 14px; every control measures at least 44px tall, verifies **AC-10**, **AC-11**
- Kit and structure: `components.json` exists, `components/ui` has the six components, no `.dark` styles, folder layout and client list as specified, verifies **AC-12**, **AC-13**
- Zoom: 1280 window at 200% zoom, all CTAs and inputs reachable, verifies **AC-14**

## Build plan

Tracer Bullet: first push one thin thread through every new layer (shadcn, token mapping, width primitives, responsive header with the Sheet) and prove it at 360 and 1440, then thicken section by section, keeping 1440 green after each.

1. Record the 1440 baseline (every section's top offset and a full page screenshot) before any change, then initialize shadcn (Radix, lucide, `components.json`), add `sheet button input tabs card avatar`, switch `lib/utils.ts` to shadcn's `cn` and remove the `cn` package, map shadcn variables to ByteSpace tokens light only, add ByteSpace variants, satisfies **AC-2**, **AC-12**
2. Add width and type foundations: `Container` rule, `Section`, `SectionHeader`, retuned heading clamps with relative line heights, responsive `body-l`, new tokens documented in tokens json and doc, satisfies **AC-1**, **AC-10**, **AC-13**
3. Tracer thread: move files into the new folders, build `SiteHeader` plus `MobileNav` (right side Sheet), verify at 360 and 1440 (menu behavior, no overflow, desktop unchanged), satisfies **AC-3**, **AC-4**, **AC-11**, **AC-13**
4. Add `ScaledCanvas` and make the hero responsive: stacked text, `HeroSearchForm` on `Input` and `Button`, scaled hero visual, ornament `from` field, eager high priority hero image, satisfies **AC-2**, **AC-5**, **AC-7**, **AC-11**
5. Courses, partners and categories: `CourseTabs` on shadcn `Tabs`, grid columns, `CourseCard` on `Card` and `Avatar`, partner grid, satisfies **AC-8**, **AC-9**, **AC-11**
6. Growth and Creator: clusters on `ScaledCanvas`, stat and revenue cards on `Card`, `HappyStudentsCard` avatars on `Avatar`, stats wrap, satisfies **AC-2**, **AC-6**
7. CTA, testimonials and `SiteFooter`: stacked CTA with full width button, testimonial grid on `Card` and `Avatar`, `NewsletterForm` on `Input` and `Button`, satisfies **AC-7**, **AC-9**, **AC-11**
8. Run the width matrix, 1440 comparison, keyboard pass, reduced motion and 200% zoom checks; run `tsc`, `eslint`, `pnpm build`, satisfies **AC-1**, **AC-2**, **AC-14**

## Consequences

**Positive**:

- Home works on phones and tablets while desktop keeps its Figma match.
- Menu, tabs and forms get tested accessibility from Radix instead of custom code (the hand written tab keyboard handler goes away).
- One kit and one width primitive make the next pages cheaper; the header and footer are ready for the app shell.

**Negative / tradeoffs**:

- Composition scaling is stepped per breakpoint band, not perfectly fluid: between band edges the scaled visual is centered with some spare space.
- Scaled cards shrink their text on small phones (the hero visual renders at about 0.4× at 360); it stays readable as decoration but is smaller than body text.
- shadcn files are copied into the repo, so upstream fixes arrive only when someone updates them by hand.
- Retuning heading tokens changes every heading below 1280, including any future page using them.

**Neutral**:

- New dependencies from shadcn init; the `cn` package leaves.
- Spec 0003's "responsive deferred" note is closed by this spec.
